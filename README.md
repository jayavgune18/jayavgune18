## Featured Projects

### 🤖 ReconcileAI Pro
> *Payment gateway + financial reconciliation platform that automates transaction matching*

**[Live Demo](https://ai-based-reconciliation-system-frontend.onrender.com)** &nbsp;·&nbsp; **[Source Code](https://github.com/jayavgune18/Ai-Based-reconciliation-system)**

Integrates **Razorpay** (UPI, Cards, NetBanking) with backend order creation, **HMAC-SHA256** signature verification, and idempotency protection against double-charging. A reconciliation engine cross-verifies gateway settlements against internal ledgers to detect exact matches, amount mismatches, duplicates, and orphan payments, with **fuzzy matching via Fuse.js**, real-time progress over **Socket.IO**, and audit-ready PDF/XLSX exports, all secured with JWT authentication.

| | |
|---|---|
| **Stack** | React · Tailwind CSS · Node.js · Express.js · MongoDB · Razorpay · Socket.IO · Fuse.js · Multer · PDFKit · XLSX · CSV-Parser · JWT · bcrypt |
| **Architecture** | Razorpay checkout → HMAC-verified orders → settlement vs. ledger reconciliation → anomaly flagging → WebSocket live progress → PDF/XLSX audit export |
| **Key features** | Verified payments · idempotency protection · automated reconciliation · duplicate & orphan payment detection · live checkout dashboard · multi-format upload (CSV/XLSX/PDF) · JWT authentication |

## Engineering Mindset

```
Production first        →  Auth, error handling, and deployment config from day one — not afterthoughts
APIs as contracts       →  Documented REST endpoints with consistent response shapes
Payments done right     →  Signature verification and idempotency so no one is charged twice
Container native        →  Docker Compose + nginx for reproducible multi-service deployments
System thinking         →  Design data flow, service boundaries, and failure modes before writing code
Clean over clever       →  Readable, maintainable, reviewable code wins every time
Fail loudly in dev      →  Fail safely in prod — meaningful error messages, no silent failures
```
